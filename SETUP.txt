 1. "COMMAND NOT FOUND" ON THIS MACHINE - THE FIX
-------------------------------------------------------------------------------
 Do NOT edit PATH. It is already correct. The terminal is just stale.

   1. Close VS Code / your terminal completely.
   2. Reopen it.
   3. Run step 5 below.

 A process only reads PATH when it starts, so a terminal opened before the
 install never sees it. Reopening is the whole fix.

 If a command is STILL missing after a full restart, check what the registry
 actually has before changing anything:

[Environment]::GetEnvironmentVariable('Path','User') -split ';'
[Environment]::GetEnvironmentVariable('Path','Machine') -split ';'

 Only if a folder is genuinely absent from both lists, add it (user scope,
 skips anything already present, no duplicates):

$add = @(
  "C:\Users\maury\AppData\Local\Programs\Python\Python312",
  "C:\Users\maury\AppData\Local\Programs\Python\Python312\Scripts",
  "C:\Program Files\nodejs",
  "C:\Program Files\GitHub CLI"
)
$key = [Microsoft.Win32.Registry]::CurrentUser.OpenSubKey('Environment', $true)
$old = $key.GetValue('Path', '', 'DoNotExpandEnvironmentNames')
$mk  = [Microsoft.Win32.Registry]::LocalMachine.OpenSubKey(
       'SYSTEM\CurrentControlSet\Control\Session Manager\Environment', $false)
$all = $old + ';' + $mk.GetValue('Path', '', 'DoNotExpandEnvironmentNames'); $mk.Close()
$parts = @($old -split ';' | Where-Object { $_.TrimEnd('\') -ne '' })
$seen  = @($all -split ';' | Where-Object { $_.TrimEnd('\') -ne '' })
$miss = @($add | Where-Object { $p = $_; -not ($seen | Where-Object { $_.TrimEnd('\') -ieq $p }) })
if ($miss) {
  $key.SetValue('Path', (($miss + $parts) -join ';'), 'ExpandString')
  Write-Host "Added: $($miss -join ', ') - reopen the terminal."
} else { Write-Host "Nothing missing. PATH is fine; reopen the terminal." }
$key.Close()

 And if `python` opens the Microsoft Store even after a restart:
 Settings > Apps > Advanced app settings > App execution aliases
 -> turn OFF "python.exe" and "python3.exe".
